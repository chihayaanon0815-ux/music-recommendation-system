## 1. 成品文件

### `data/processed/songs.csv`

编码 UTF-8（无 BOM），逗号分隔，含表头，**行尾 LF（0 个 CRLF）**；每行一首歌；**89,740 行，约 6.4 MB**；按 `song_id` 字符串字典序升序。

| 列 | 类型 | 非空 | 说明 |

| song_name | string | 是 | 曲目名，已去首尾空格；字段内英文双引号已规范为单引号 |

### `data/processed/genre_counts.csv`

编码 UTF-8（无 BOM），表头 `genre,count`，**31 行**。每首歌的每个不同大类计 1 次；按 count 降序、genre 升序排序。计数范围 996–15,556。

### 分类口径（写明，便于复核）

1. **曲风为主**：摇滚/朋克/金属等按音乐流派归并，`另类`、`独立`、`英伦` 等 Spotify 的摇滚/独立标签归入摇滚。
2. **语言类流行双挂**：`华语流行/粤语流行` 同时属于「流行」和「华语流行」，`日式流行/韩式流行/日系偶像/日式舞曲` 同时属于「流行」和「日韩流行」。因此用户选「流行」能拿到中文/日韩流行，选「华语流行」只拿中文流行。这正是酷狗“语种 + 曲风”两个维度压进一列后的近似做法。
3. **语言类非流行标签**（法语、德语、西班牙语、瑞典语、印度、马来语、土耳其、伊朗、巴西等）归入「世界音乐」，不再单独保留语种轴。
4. **场景/心情/人群独立成类**（伤感、欢快、浪漫、放松、助眠、学习、派对、儿童、ACG、影视、喜剧）：这些在原始数据里本来就是标签，强行塞进曲风会失真，因此保留为独立大类——与酷狗的“心情/场景”轴对应。
5. **其他细节**：`原声`归民谣（原声弹唱），`斯卡`归雷鬼（牙买加音乐系），`回响`归雷鬼、`回响贝斯`归电子，`工业`归电子，`福音`归灵魂乐，`歌剧`归古典，`钢琴/吉他/氛围/新世纪`归轻音乐。
6. **一个细分标签只进一个大类**，类别边界见上表；映射表本身是 `data_processing/genre_map_zh.csv`（三列：英文、中文细分、大类），改动后重跑下载与清洗即可。

## 3. 清洗规则（与 `data_processing/clean_songs.py` 一致）

输入：`data/raw/spotify_tracks_raw.csv`（由下载脚本生成，含 `genres`=大类、`genres_zh`=细分、`genres_en`=英文）。

1. **去空格**：四列全部 `trim`。
2. **剔除空键**：`song_id` 或 `song_name` 为空的记录剔除。本次 114,000 行中剔除 1 行。
3. **标签规范化**：按 `|` 切分 → 逐项 `trim` → 丢弃空项 → 去重 → 按字符序排序 → 用 `|` 连接。
4. **重复 ID 合并**：`song_id` 相同的多行合并为一条：
   - `genres` 取所有行的**并集**（细分标签先变成大类，再并集去重，所以 `另类|另类摇滚|摇滚` 会合并为「摇滚」）；
   - `song_name` 取最小非空值，`artist` 取最小非空值；都为空时 artist 为空字符串。
   - 规则与输入行序、Spark 分区无关，结果确定。
5. **空风格**：允许，成品中为空字符串，不计入 `genre_counts.csv`。
6. **不转大小写**：标签、歌手按原字符串精确比较（供 B 的算法使用）。
7. **排序**：`songs.csv` 按 `song_id` 字符串字典序（非数字序）。

## 5. 与统一契约的关系

字段、排序、空值、`|` 分隔、正分推荐所需字段均遵循仓库 README “统一契约 v1”。页面风格选项应取自已加载数据的唯一标签（31 个大类），不要硬编码其它写法。

风格映射表 `data_processing/genre_map_zh.csv`：114 行，英文原文 -> 中文细分 -> 大类；保证“一个英文标签只对应一个中文细分名”，中文细分名互不重复；大类允许重叠（见第 2 节口径 2）。映射是人工整理，不是官方译名。

## 6. 已知限制（如实记录）

- 大类是人工归并，边界有主观成分（例如 `工业` 归电子、`车库摇滚` 归摇滚）；答辩时以 `genres_zh`/`genres_en` 的细分为准可自证。
- 语言轴没有单独保留：`法语/德语/…` 等归入世界音乐，华语/日韩流行通过双挂体现；因此不能用 `genres` 做“语种统计”。
- 场景/心情类（伤感、助眠等）并非严格意义的曲风，与酷狗的“心情/场景”轴对应；本数据把它们作为独立大类保留。
- 同一首歌可能以不同 track_id 多次出现（专辑版/单曲版），本项目按 track_id 去重，不按歌名合并。
- 数据集按细分风格均衡抽样（每细分约 1000 行），大类计数接近但不等；风格计数不能用来论证“市场流行度”。
- 数据为 2022 年前后采集的快照，popularity 会随时间变化；本仓库不再更新。
- 数据集许可链见 `sources_and_licenses.md`：ODbL 数据库 + 内容版权归原作者，且底层来自 Spotify API，不属于 CC0。
