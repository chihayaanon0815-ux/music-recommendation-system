# 新版曲库工作总结与复现说明

交接日期为 2026 年 11 月 24 日。数据版本为 `2026-11-24-reviewed`，网页试玩固定在 GitHub `main` 提交 `9566ec187f266b673ff6c316050ce970758bddf1`。

## 1. 目标与交付

从原有曲库出发，以歌手、乐队、艺人为单位扩充曲目。名单优先覆盖华语艺人，同时补充不同地区和流派。以规范化歌名和艺人署名识别重复，保留不同版本、别名和合作署名的来源记录。后续按课程组决定保留已进入清洗曲库的全部记录，疑似重复另表复核。全量最终为 **293,864 条**，超过最初“合并后约 20 万首”的目标。经名称规则归并后，本轮带来 **213,214 个新增键**。

最终运行文件位于 `outputs/新版曲库-复核版/`。歌曲为 UTF-8 CSV，列为 `song_id,song_name,artist,genres`，多标签以竖线分隔。歌曲 ID 唯一，可用于关联验收表与权重表。`genre_counts.csv` 按每首的不同标签各计一次，总和可超过曲目数。交付内容为曲目元数据、来源证据、脚本和试玩源码。

## 2. 艺人名单与采集

- 先试跑 MusicBrainz 的艺人、正式发行和录音目录，观察同名身份识别、别名、同作品多版本以及专辑分页问题。首版 321 个名称，新增 679 个，最终形成 1,000 个去重名称。
- 华语优先规划含 283 个首版和人工补充名称，以及 117 个由原库华语标签选出的候选。其余包括欧美 72、日韩 42、其他地区 26、地区待核实 460。这些数字描述名单选择依据，曲目语种和地区均衡度尚未实测。
- 首轮逐名查询 Apple iTunes Search，遇到身份不明确、结果较少或触及返回上限时用 Deezer、MusicBrainz 补查。目录补采按艺人遍历 Apple 专辑和曲目，必要时分页查 Deezer 专辑及曲目、MusicBrainz 录音。脚本按艺人写检查点，支持续跑、重试空结果、从检查点重新导出。
- 全部名称执行首轮和目录补采。910 个名称取得曲目，90 个未取得。718 个名称的补采记录带待核实情况，涉及专辑不完整、查询上限、失败、同名歧义或空结果。目录完整度受平台收录和接口上限影响。

| 采集口径 | 数量 |
| --- | ---: |
| 去重后的采集候选 | 222,946 |
| 候选中原有标签 | 199,665（89.56%） |

| 来源观察记录 | 388,288 |

## 3. 合并清洗与标签整理

1. **归并新旧数据。** 原库 89,740 行归为 80,650 个规范化键。222,946 个采集候选与原库重叠 9,732 键。初次合并输入 312,686 行，归并 18,822 行，无无效行被剔除，得到 293,864 条。规则处理大小写、空白、简繁、已知艺名和可识别的现场或重制后缀。用 `row_lineage.csv` 追溯来源，用 `removed_rows.csv` 查看归并行。
2. **优先补曲目证据。** 清洗后有 22,523 条标签为空。第一轮利用缓存及曲名、艺人精确匹配补 2,724 条。扩大检索的一轮重点查 65 位艺人，曲目匹配补 399 条，艺人风格估计补 7,430 条。随后结合合作艺人一致性、主艺人及署名顺序补齐。此时有 7,841 条带待确认标记。
3. **统一标签语义。** 将 489 种输入标签写法映射到 21 种推荐曲风与其他属性，保留地区语种、情绪场景、内容类型、版本、年代等细节。此轮有 50,855 首缺少可直接用于推荐的曲风。相关映射见 `label_mapping.csv`、`source_label_mapping.csv` 与 `song_label_details.csv`。
4. **继续核查和填补。** 先结合原曲目标签、内容类别和艺人风格，待确认缩至 14,945 条。再针对 80 位艺人补查 MusicBrainz、不同地区的 Apple 曲库与 Audius，增加 42 条可确认曲目标签。最后根据同艺人、合作艺人、标题与已有标签等信息推断，证据最弱时使用全库频率兜底。曲风补全阶段的统计为 290,939 条有音乐曲风，2,925 条标作非音乐内容，全部保留。标题模型在留出艺人的测试中标签匹配率为 39.7%，同批频率基线为 30.1%，该结果衡量标签复现能力。

当前默认推断权重建议为已有标签或确认曲目 1、艺人推断 0.5、模型估计或跨平台冲突 0.25、仅靠全库频率兜底 0。权重表实际有 107、31,198、27,396、723 条记录分别使用这四种权重，其他曲目按默认处理。`exclude_from_genre_ranking.csv` 列出 723 条兜底曲目，仍可按歌名或艺人查找。规则待推荐算法联调。

最终证据见 `duplicate_review.csv`、`genre_conflict_review.csv`、`stratified_audit.csv` 与 `manifest.json`。公共 GitHub 分支提供新版清单和校验工具，完整新版曲库和逐曲来源在本地交接包。混合数据中部分来源的再分发授权尚未确认，本包用于课程组内交接。 [GitHub 曲库版本目录](https://github.com/chihayaanon0815-ux/music-recommendation-system/tree/data/catalog-reviewed-2026-11-24/docs/data/catalog-reviewed-2026-11-24)

## 5. 网页试玩

此次试玩只替换曲库和统计文件。使用固定的 `main` 代码快照，保留正式推荐模块和歌单功能。首次使用本地歌单搜索时根据歌曲 CSV 建 SQLite 索引。试玩歌单数据库与平时使用的数据分开存储。从 ZIP 解压到含中文的路径后，已通过 HTTP 验证首页、默认推荐、摇滚和歌手筛选、推荐理由、未知歌手提示、两张图表的页面内容、歌单创建和本地曲库搜索。SQLite 实际索引 293,864 首。上一阶段 Flask 测试客户端曾记录默认推荐 1.503 秒、摇滚 1.071 秒、艺人 1.021 秒，属于当时工作区的服务端记录。新快照的浏览器交互表现仍由组内试玩验收。 [试玩所用 main 提交](https://github.com/chihayaanon0815-ux/music-recommendation-system/commit/9566ec187f266b673ff6c316050ce970758bddf1)

解压后在交接包根目录通过 PowerShell 启动。要求 Python 3.11 或更新版本，第一次安装 Flask 需要依赖来源。

```powershell
python -m pip install "Flask>=3.0,<4"
python start_preview.py
```

打开 [本地试玩](http://127.0.0.1:5074/)。若旧试玩占用该端口，可用 `python start_preview.py --port 5075` 并访问对应端口。在启动终端按 Ctrl+C 退出。测试歌单保存在包内 `work/main-catalog-preview/test-user-data/`。在线补查需要网络。此次交接为源码和数据包，Windows 独立可执行程序及另一台无 Python、Java、网络电脑的验收待完成。

## 6. 脚本和复现顺序

在解压后的副本操作。多数历史脚本按本包的 `work/`、`outputs/` 相对结构读写文件，重跑会覆盖对应阶段的结果。

| 阶段 | 脚本及用途 |
| --- | --- |
| 试采与名单 | `work/` 下的 `*_pilot.py`、`build_artist_roster.py`、`expand_artist_roster.py` 为试采与名单整理脚本。正式扩充入口为 `work/music_collector/expand_to_1000.py` |
| 首轮和深度采集 | `catalog.py` 为正式采集入口，`collect.py` 为早期 MusicBrainz 试采。 `publish_progress.py` 导出进度，`complete_catalog.py` 汇总并执行目录补采，`final_stats.py` 生成最终采集统计 |
| 合并清洗 | `prepare_cleanup.py`，读原库快照和采集候选，生成归并、标签初步映射和来源追溯 |
| 补齐缺失标签 | `fill_missing_genres.py` → `search_missing_genres.py` → `finalize_missing_genres.py`。逐轮结果与证据随包提供 |
| 统一标签和全量覆盖 | `unify_taxonomy.py` → `confirm_catalog_genres.py` → `verify_more_genres.py` → `assign_all_genres.py` |
| 验收与发布 | `audit_full_catalog.py` → `audit_title_variants.py` → `correct_audited_genres.py` → `review_release.py`。最终用 `verify_catalog_release.py` 校验 |

表内未写前缀的脚本位于 `work/music_collector/`。全新采集在 Windows 上使用 Python 和 `curl.exe`，以下示例在新的状态目录运行，复用同一个 `--work` 可继续采集。

```powershell
python work/music_collector/catalog.py outputs/艺人扩充1000/artists_1000.csv --work work/new-collection
python work/music_collector/catalog.py outputs/艺人扩充1000/artists_1000.csv --work work/new-collection --deep
# 从已有深度检查点重新导出，或去掉 --export-only 并加 --retry-empty 重试空结果
python work/music_collector/catalog.py outputs/艺人扩充1000/artists_1000.csv --work work/new-collection --deep --export-only
```

交接包保留本轮两个正式检查点、原始四列旧库、来源索引、各阶段 CSV 和报告，以及扩大检索和质量抽查的缓存。早期全量 HTTP 缓存 `work/catalog_run/cache/` 和试采原始响应未收录。重新运行依赖该缓存的早期补标签脚本时，从随包保留的该阶段结果开始可避免缺少历史缓存造成差异。重新联网运行时，平台目录和可用性可能变化。

只验收最终包，或从归档的质量验收结果重跑最后一次复核，可用以下命令。

```powershell
python outputs/新版曲库-复核版/verify_catalog_release.py outputs/新版曲库-复核版
python work/music_collector/review_release.py
python outputs/新版曲库-复核版/verify_catalog_release.py outputs/新版曲库-复核版
```

已在解压副本中完成复核重跑。歌曲 CSV、风格统计及其他复核文件与原包哈希一致。冲突表中的 JSON 字段可能按不同顺序列出各风格的投票数，字段含义和数值经对比一致，重跑会为生成的文件重新计算哈希。原封包的清单与 GitHub 上公开的版本清单对应。
