# 已知限制与未验证项

本文件如实记录 B 模块做不到什么。报告与答辩引用限制时以本文件为准。

## 1. 模块定位

这是课程项目的**规则打分推荐**，目标是满足契约 v1 并做到可解释、可复现，而不是效果最优的推荐系统。它没有训练过程，没有模型文件，换一台机器跑出完全一样的结果。

## 2. 算法限制（如实记录）

| 限制 | 具体表现 |
| --- | --- |
| 只做精确字符串匹配 | `Pop` 与 `pop`、`流行` 与 `流行音乐` 都算不同；不做同义词、别名、大小写归并 |
| 权重固定 | 风格 3 分、歌手 2 分写死在常量里，页面不能调 |
| 不考虑热度 | 没有播放量、收藏数、评论数，所以无法做“热门”排序 |
| 不考虑用户历史 | 每次只看当次选择的偏好，不记忆上次选择 |
| 无多样性控制 | 同风格高分歌曲会连续排在前列，没有打散或配额 |
| 无分页 | 一次最多 `limit` 条，超出部分不提供翻页 |
| 无模糊/语义匹配 | 拼错、简称、中英混写都命中不了 |
| 歌手只认完全相同 | “周杰伦”与“周杰伦（Jay）”不匹配 |

## 3. 数据限制

- 包内只有 `tests/recommender/sample_songs.json`，**5 首虚构歌曲**，仅用于测试，不可当业务数据；
- 真实数据由 A 提供（清洗后 `data/processed/songs.csv`，89,740 首），本包不含；
- 因此本包**没有**任何基于真实数据的分布统计、覆盖率或效果数字；
- 若 A 的数据里存在同一歌手的多种写法，本模块会把它们当成不同歌手，需要 A 在清洗阶段统一。

## 5. 合规红线

- 不使用、不存储任何真实用户信息、账号、听歌记录；
- 不做爬虫，不抓取第三方平台数据；
- 不引入第三方依赖，避免许可传染；
- 不声称任何效果指标（准确率、召回率、NDCG、点击率提升），因为没有做过评估；
- 报告里若写“推荐准确”，必须改成“按契约打分、理由可复算”。
