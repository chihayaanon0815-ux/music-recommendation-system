# 推荐算法规格与实现规则

本文件描述 `recommender/recommend.py` 的实现口径。它是**规则打分**，不是训练模型：所有分值都能手工复算。

## 1. 模块与契约

### `recommender/recommend.py`

| 项目 | 内容 |
| --- | --- |
| 对外函数 | `recommend(songs, preferences, limit=10)` |
| 依赖 | Python 标准库（无第三方包） |
| 权重常量 | `GENRE_WEIGHT=3`、`ARTIST_WEIGHT=2`、`DEFAULT_LIMIT=10` |
| 契约版本 | v1（根 `README.md`） |
| 是否改契约 | 否 |

## 2. 输入与输出

### 输入

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `songs` | `list[dict]` | 每项含 `song_id, song_name, artist, genres`，均为字符串；`genres` 用 `\|` 分隔 |
| `preferences` | `dict` | `{"genres": [...], "artists": [...]}`；缺键或 `None` 视为空列表 |
| `limit` | `int` | 最多返回条数，默认 10 |

### 输出

新的 `list[dict]`，每项字段固定：

```text
song_id, song_name, artist, genres, score, reason
```

`score` 为整数，`reason` 非空；输入列表与偏好字典都不会被修改。

## 3. 评分规则

| 命中项 | 分值 |
| --- | --- |
| 每个**不同**风格标签 | +3 |
| **歌手精确匹配**（非空且完全相同） | +2 |

- 一首歌最多 `3 × 命中风格数 + 2` 分；
- 重复选择的偏好项、歌曲里重复的标签都只算一次（集合语义）；
- 空歌手、空标签不参与匹配。

## 4. 处理流程（与 `recommender/recommend.py` 一致）

```text
1. 规范化偏好：取 genres/artists，缺键为空；每项 strip、丢空、按首次出现去重
2. limit <= 0 → 直接返回 []
3. 遍历 songs：
   a. song_id、song_name strip 后任一为空 → 跳过
   b. song_id 已出现过 → 跳过（保留首次出现）
   c. genres 按 '|' 切分、strip、去空、去重
   d. 命中风格 = 交集，按字符串排序
   e. 歌手命中 = 歌手去空格后与任一偏好歌手完全相同（且非空）
   f. score = 3 × 命中风格数 + (2 if 歌手命中 else 0)
   g. 有偏好且 score <= 0 → 丢弃；score > 0 → 生成理由
   h. 无偏好 → score = 0，reason = 默认推荐文案
4. 排序：score 降序，同分按 song_id 字符串升序
5. 截断：取前 limit 条
```

## 5. 排序、截断与边界

### 排序

- 主键 `score` 降序；次键 `song_id` 按**字符串**字典序（不是数字序）：`"01" < "10" < "2"`。
- `limit` 是上限：命中有多少返回多少，不补齐；`limit=0` 或负数返回 `[]`。
- `limit` 传入非 `int`（字符串、布尔等）抛 `TypeError`；`limit=None` 按默认 10。

### 边界行为表

| 场景 | 行为 |
| --- | --- |
| 未选择任何偏好 | 返回全部歌曲（按 ID 排序），`score=0`，理由含“默认推荐” |
| `preferences={}` | 同上（缺键视为空） |
| 有偏好、有命中 | 只返回正分，按规则排序 |
| 有偏好、无命中 | 返回 `[]` |
| `limit=0` 或负数 | 返回 `[]` |
| 命中数 < `limit` | 返回实际命中数，不补齐 |
| 记录缺 `song_id` 或 `song_name` | 跳过该记录 |
| `song_id` 重复 | 保留首次出现，后续跳过 |
| 偏好含重复项 / 歌曲标签重复 | 去重，不重复加分 |
| 偏好项含首尾空格 | 去空格后比较 |
| 大小写不同（`Pop` vs `pop`） | 视为不同，不命中 |
| 歌手为空 / `genres` 为空串 | 不参与匹配 |

## 6. 理由生成（可解释性）

| 情况 | 生成结果 |
| --- | --- |
| 风格 + 歌手双命中 | `风格匹配：流行；歌手匹配：测试歌手` |
| 仅风格（多标签） | `风格匹配：民谣、流行`（标签按字符串升序） |
| 仅歌手 | `歌手匹配：测试歌手` |
| 无偏好 | `默认推荐：未选择偏好，按 song_id 字典序展示` |

理由只列**实际命中**的项；没有命中就不进入结果，因此不会出现空理由，也不会出现“可能喜欢”这类不可核对的措辞。

## 7. 复杂度与实测结果

- 扫描 + 打分 O(n × (g + a))，排序 O(m log m)，内存 O(m)；
- 实测：23 项测试总耗时 0.002 秒（Windows / Python 3.13.18，2026-11-21）；
- 8.9 万首规模理论为毫秒级，页面每次请求重算即可，无需缓存。

## 8. 与统一契约的关系

| 契约条目 | 实现位置 |
| --- | --- |
| 每命中风格 +3 | `GENRE_WEIGHT` |
| 歌手精确 +2 | `ARTIST_WEIGHT` |
| 只返回正分 | `if score <= 0: continue` |
| 同分按 ID 字符串序 | `sort(key=(-score, song_id))` |
| 无偏好默认推荐 | `DEFAULT_REASON` 分支 |
| `limit` 非正为空 | 函数入口判断 |
| 不修改输入 | 只读 + 新建字典 |
| 返回六个字段 | `results.append({...})` |

## 9. 已知限制（如实记录）

- 只认精确字符串，`Pop`/`pop`、`流行`/`流行音乐` 都视为不同；
- 权重固定，不可配置；
- 不做隐式偏好推断，不选就只给默认推荐；
- 无多样性重排，同风格可能连续出现；
- 无分页，一次最多 `limit` 条；
- 未使用播放量、用户行为、协同过滤或音频特征，因此没有任何效果指标可报告。

详见 `docs/recommendation/limitations.md`。
