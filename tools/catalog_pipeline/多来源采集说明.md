# 艺人歌曲采集

解压后用 Python 3.10 或更新版本运行，输入是随附的 1000 个艺人名称。Windows 上会归一化简繁体以辅助匹配，联网查询依赖 curl.exe。

```powershell
python catalog.py artists.csv --work state
```

普通模式逐一搜索 Apple iTunes 曲库。如果没有可靠身份、结果太少或达到搜索上限，就查询 Deezer 和 MusicBrainz。普通模式用来统计全名单首轮产量，Apple 搜索最多返回 200 项，Deezer 和 MusicBrainz 补查也可能只获得部分曲目。

```powershell
python catalog.py artists.csv --work state --deep
```

深度模式按艺人查 Apple 专辑并提取曲目。需要补查时分页遍历 Deezer 专辑及曲目，或分页查 MusicBrainz 录音。Apple 的公开查询有返回上限，各站目录也可能存在缺漏。深度模式独立保存进度，两种模式共用请求缓存。保留相同工作目录再运行即可续采。用 `--retry-empty` 可重试没有曲目的艺人。

程序每完成一位艺人便保存进度，每五位更新 CSV。可用 `--export-only` 从进度文件重新导出。

- `songs_candidates.csv` 沿用 UTF-8 四列 `song_id,song_name,artist,genres`。艺人及歌名经规范化后相同的记录只留一行，已识别的现场、重制等版本后缀会去掉。已知艺名共用同一个去重键。
- `sources.csv` 保存各站曲目 ID、原曲名、艺人署名和原始风格。优先选无版本后缀且有风格的记录，同等条件下优先 Apple、Deezer、MusicBrainz。
- `artists.csv` 记录逐位采集数量、同名歧义、查询上限、失败和补查状态。已知艺名表不完整，候选标题或风格仍需后续核对。

Apple 速率限制见 [官方 Search API 文档](https://performance-partners.apple.com/search-api)。MusicBrainz 补查遵守[请求频率限制](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting)。程序采集曲目元数据，未下载音频。
